# 친구 도전장 + 빠른 답 점수 설계 (1단계)

- **작성일**: 2026-10-09
- **상태**: 확정
- **배경**: 여러 명이 경쟁하는 구조로 가기 위한 1단계. 서버 없이(정적 내보내기 `output: 'export'`) 친구끼리 같은 문제로 비동기 대결을 하게 만든다. 실시간 친구방(2단계)과 정기 공개 이벤트(3단계)는 이 문서의 범위가 아니다.

## 1. 목표
1. 모든 판에 "빨리 맞힐수록 높은 점수"를 적용해 기록 경신 욕구를 만든다.
2. 도전장 링크로 친구가 **같은 5문제**를 풀고 점수를 비교하게 한다.
3. 받은 사람이 다시 도전장을 보내는 "되받아치기"로 공유가 계속 이어지게 한다.

## 2. 점수 규칙 (모든 판에 적용)
- 문제당 제한 시간은 **15초**(기존 유지).
- 정답 점수: `round(500 + 500 × (min(남은 시간, 15) ÷ 15))`
  - 남은 시간은 0.1초 단위로 측정한다.
  - +10초 파워업을 써서 남은 시간이 15초를 넘어도 15초로 계산한다. 즉 +10초는 타이머만 늘려 주고 점수 이득은 없다.
- 해당 문제에서 50:50이나 힌트를 썼으면 위 점수의 **절반**(`round(점수 ÷ 2)`)을 받는다.
- 오답 / 시간 초과: 0점.
- 만점: 5문제 × 1,000 = 5,000점.
- 등급(칭호)은 기존처럼 **맞힌 개수** 기준을 유지한다.
- XP 지급 방식은 기존 그대로 유지한다(정답 20 XP, 완주 30 XP).

## 3. 사용자 흐름

### 3.1 도전자 (A)
1. 평소처럼 퀴즈를 푼다. 정답을 맞히면 "+870"처럼 그 문제 점수가 바로 표시된다.
2. 결과 화면 맨 위에 총점(예: `3,840 / 5,000`)을 크게 보여주고, "5문제 중 4개 정답"을 작게 보여준다.
3. "친구에게 도전장 복사"를 누르면 닉네임 입력칸이 나온다(선택, 최대 12자). 입력값은 `localStorage`의 `kpulse_nickname`에 저장해 다음부터 자동으로 채운다.
4. 복사되는 문구에는 총점과 도전장 링크가 들어간다. X·Reddit·기기 공유도 같은 도전장 링크를 쓴다.

### 3.2 도전받는 친구 (B)
1. `?c=` 값이 있는 링크로 들어오면 시작 화면 맨 위에 도전장 배너가 나온다.
   - 예: "⚔️ Minji님이 도전장을 보냈어요! 점수: 3,840점. 이길 수 있나요?"
2. 대결 모드에서는 난이도 선택을 숨기고, A와 같은 5문제를 같은 순서로 낸다.
3. 문제를 풀 때마다 상단에 A의 같은 문제까지 누적 점수와 비교한 차이를 보여준다("+120 앞섬" / "-300 뒤짐" / "동점").
4. 결과 화면에서 문제별 A vs B 점수 비교표와 승리 / 패배 / 무승부를 보여준다.
5. "되받아치기 도전장 보내기" 버튼으로 같은 5문제에 B의 점수와 닉네임을 담은 새 링크를 만든다.
6. 대결이 끝난 뒤 "다시 하기"를 누르면 `?c=`를 주소에서 지우고 일반 모드로 시작한다.

### 3.3 예외 처리
- 링크 디코딩 실패, 검증값 불일치, 지원하지 않는 버전, 현재 문제은행에 없는 문제 ID, 문제 수가 5개가 아닌 경우 → "도전장이 만료됐거나 잘못된 링크예요" 안내를 띄우고 일반 모드로 시작한다.
- 자기 자신의 도전장 링크를 열어도 막지 않고 대결 모드로 진행한다.
- 닉네임이 비어 있으면 화면에서는 번역된 "친구"(예: "A friend")로 표시한다.

## 4. 도전장 링크 형식

```
/quiz/<slug>?c=<payload>
```

`payload`는 아래 JSON을 UTF-8 → URL-safe base64(패딩 없음)로 바꾼 값이다.

| 필드 | 타입 | 내용 |
|---|---|---|
| `v` | number | 형식 버전. 현재 `1` |
| `q` | number[5] | 출제 순서대로의 문제 ID |
| `p` | number[5] | 도전자의 문제별 점수(각 0~1000 정수) |
| `n` | string | 닉네임(0~12자, 앞뒤 공백 제거) |
| `h` | string | 검증값 |

- 검증값 `h`: 퀴즈 slug, `v`, `q`, `p`, `n`을 이어 붙인 문자열에 고정 salt를 더해 FNV-1a 32비트 해시를 구한 뒤 base36으로 바꾼 값. 클라이언트 코드에 salt가 들어 있으므로 보안 장치가 아니라 **링크 속 숫자를 손으로 고치는 정도의 조작을 막는 용도**다.
- slug를 검증값에 포함하므로 다른 퀴즈 경로에 같은 `c`를 붙이면 거부된다.
- 총점은 링크에 넣지 않고 `p`의 합으로 계산한다.
- 링크 미리보기(OG) 이미지는 기존 퀴즈 배너를 그대로 쓴다. 점수가 들어간 미리보기는 서버가 생기는 2단계에서 다룬다.

## 5. 코드 구성

`QuizRunner.tsx`가 이미 1,000줄이 넘으므로 새 로직은 별도 파일로 분리한다.

| 파일 | 구분 | 역할 |
|---|---|---|
| `src/lib/scoring.ts` | 신규 | `calcQuestionPoints({ correct, remainingSec, usedAssist })` 등 점수 공식만 담은 순수 함수와 상수(`QUESTION_TIME_SEC = 15`, `MAX_POINTS_PER_QUESTION = 1000`) |
| `src/lib/challenge.ts` | 신규 | `encodeChallenge(slug, data)`, `decodeChallenge(slug, payload)` → 성공 시 데이터, 실패 시 `null`. `resolveChallengeQuestions(quiz, ids)` → 문제 배열 또는 `null` |
| `src/components/ChallengeBanner.tsx` | 신규 | 시작 화면 도전장 배너, 풀이 중 앞섬/뒤짐 표시 |
| `src/components/ChallengeResult.tsx` | 신규 | 문제별 비교표, 승패 표시, 되받아치기 버튼 |
| `src/components/QuizRunner.tsx` | 수정 | 문제별 점수와 남은 시간(0.1초 단위) 기록, 파워업 사용 여부 기록, `?c=`가 유효하면 대결 모드로 시작, 결과 화면 총점 표시 |
| `src/components/ShareButtons.tsx` | 수정 | 닉네임 입력, 도전장 링크 생성, 공유 문구에 총점 표시 |
| `src/lib/translations.ts` | 수정 | 새 문구를 지원 언어 5개(ko, en, es, ru, zh) 모두에 추가 |

구현 메모:
- 정적 내보내기 구조이므로 `?c=` 값은 브라우저에서 읽는다. 이 프로젝트의 Next.js 16 방식(`useSearchParams`와 Suspense 경계 등)은 구현 전에 `node_modules/next/dist/docs/`에서 확인한다.
- 현재 타이머는 1초 단위 `setInterval`이다. 점수용 남은 시간은 문제 시작 시각과 제출 시각(`Date.now()`)의 차이로 계산하고, +10초 사용분을 더한 실제 제한 시간에서 뺀다. 화면 표시용 카운트다운은 기존 방식을 유지해도 된다.
- 대결 모드에서도 파워업은 그대로 쓸 수 있다(점수 규칙이 같으므로 공정하다).

## 6. 테스트
- 개발 의존성으로 **Vitest**를 추가하고 `npm test` 스크립트를 만든다.
- `scoring.ts` 단위 테스트: 남은 시간 15초 만점(1000), 0초(500), 오답(0), 파워업 절반, +10초로 남은 시간이 15초를 넘을 때 상한 적용, 반올림.
- `challenge.ts` 단위 테스트: 인코딩 후 디코딩 시 원래 값과 동일, 한글·이모지 닉네임 처리, `p` 값 조작 시 거부, 다른 slug에서 거부, 잘못된 base64·JSON 거부, 버전 불일치 거부, 문제은행에 없는 ID 처리, 점수 범위 밖 값 거부.
- 수동 확인: 브라우저 창 두 개로 도전 → 받기 → 되받아치기 흐름, 만료 링크 안내, 모바일 폭 화면, `npm run build` 성공.

## 7. 범위 밖
- 실시간 대결, 방 만들기, 서버 저장(2단계).
- 한 링크에 여러 친구 점수를 모으는 순위표(서버 필요).
- 점수가 들어간 동적 OG 이미지.
- 강력한 부정행위 방지.
